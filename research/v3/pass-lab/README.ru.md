# L02B и Baseline: проверка выбора паса, 27 октября 2026

Владелец остановил M11 после наблюдения пасов мимо своих игроков и перенаправил
работу на L02B и Baseline. M11 закончил четыре игры: 2W/2L, 6:6. Четвёртая
игра уже завершилась 0:2; она не была прервана. Ремонт M11 не выполняется.

Канонический Baseline восстановлен, все пять точных привязок проверены,
формация 1-1-2, фактический свежий Fitness 5/5. Владелец затем разрешил
Baseline играть, пока локальная аналитическая работа продолжается. Новые
native probes, изменения состава и deployment во время игр запрещены.

## Что удалось установить

- L01, используемый L02B и M11 с мячом, выбирает адресата из `state.teammates`.
  Команда определяется вместе с `agentId`, а не только по повторяющемуся номеру.
  В доступных данных ошибка отправки команды чужому адресату не подтверждена.
- В последней игре M11 зарегистрированы 6 отправленных MID PASS. Старый лог
  не сохранял адресата или результат передачи, поэтому замеченные владельцем
  эпизоды нельзя достоверно привязать к этим шести командам.
- Для L02B локально добавлены адресат, геометрическая система, свидетельство
  владения, число доступных адресатов и показатели линии/опеки. `passCompleted`
  и `ballRetained` остаются `null`: отправленная команда не доказывает успех.
  Тактическая политика не меняется; диагностическая сборка не развёрнута.
  Проверены HTTP-ответ без изменения, ограниченность журнала и существующие
  guards: 35 локальных тестов прошли.

## Изолированная проверка Baseline

До запуска первого матча Baseline выполнены 20 вызовов сохранённого неизменного
MID15/Nova2Lite. По одной новой сессии на ситуацию; все 20 сессий закрыты.
План заранее записан в `plan.json`. Есть HOME/AWAY и XY/контрфактический XZ;
четыре ситуации адресата плюс явное владение соперника с тем же `agentId_2`.
Это искусственные состояния, не дополнительные игровые наблюдения.

| Показатель | Baseline MID |
|---|---:|
| Ответы, корректные по схеме после удаления Markdown fences | 20/20 |
| Ответы с Markdown fences | 13/20 |
| Команды, противоречащие явному владению | 5/20 |
| Выданные PASS | 10 |
| PASS с несуществующим своим адресатом | 0/10 |
| PASS, которые отвергла бы эвристика линии/опеки L01 | 6/10 |
| Полный локальный вызов в новой сессии: медиана | 3446 мс |
| Полный локальный вызов в новой сессии: p95 | 33286 мс |
| Полный локальный вызов: диапазон | 1518–34769 мс |

Три противоречия — PRESS_BALL при явном собственном владении AWAY/XZ;
ещё два — PASS, когда явный владелец на стороне соперника, тоже AWAY.
У всех выданных PASS есть адресат на собственной стороне по контракту команды;
это не проверяет фактическую траекторию или принятие команды игровым сервером.
Шесть спорных пасов идут в закрытую линию либо к опекаемому игроку в построенных
ситуациях. Эвристика L01 не является вероятностью перехвата или физическим
симулятором. Совпадение с L01 не используется как единственный критерий качества.

Время включает весь локальный SDK/сессию; оно не равно времени модели или
задержке игрового сервера. Удаление fences — только аналитическая обработка,
не подтверждение терпимости игрового парсера. Один ответ на состояние не
устанавливает воспроизводимость модели. Сырая запись и идентификаторы приватны;
обезличенные команды, расчёты и ограничения — в `baseline-results.json`.

## Одно следующее изменение

Подготовлен P05: явное сопоставление teamId/teamCode и agentId при определении
своего игрока, владения и адресата. Это уточнение идентичности, без изменения
модели, координат, тактических порогов или остальных ролей. Новые обязательные
поля владения не вводятся. Исходный промпт Baseline сохранён.

P05 пока не прошёл native-сравнение, не зарегистрирован и не является усилением
с доказанным игровым результатом. Проверять его можно только между матчами,
на том же плане и с точным readback отдельной конфигурации. Сначала устранение
противоречий явному владению; настройка линии паса — отдельная гипотеза P04.
Откат: канонический MID15 и свежий Fitness 5/5. Турнирного продвижения нет.
