## Порядок восстановления

1. Войти в новый Workshop, дождаться готовой инфраструктуры и получить новую execution role. Скрипт не создаёт IAM-роли и не меняет политики. Если нужный вызов запрещён, сохранить ошибку и проверить разрешённый путь Workshop.
2. Склонировать репозиторий и выбрать сохранённый commit/tag. Старые runtime и Harness ARN повторно использовать нельзя.
3. Подготовить Python 3.10+ и актуальный boto3. Схемы запросов проверены с boto3/botocore `1.43.118`. Устаревший SDK может не содержать Harness API.
4. Сначала посмотреть план. Команда ниже не создаёт AWS-клиент и не обращается в сеть:

```sh
python3 research/v3/recovery/restore.py --profile baseline-m8
```

5. Для создания передать execution role **нового** Workshop. Префикс должен быть свободным; скрипт создаёт отдельные ресурсы и не перезаписывает существующие.

```sh
python3 -m venv .local/recovery-venv
.local/recovery-venv/bin/pip install 'boto3>=1.43.118'
.local/recovery-venv/bin/python research/v3/recovery/restore.py \
  --profile baseline-m8 \
  --prefix nhitl_restore \
  --execution-role-arn "$NEW_WORKSHOP_EXECUTION_ROLE_ARN" \
  --receipt .local/recovery/receipt.json \
  --apply
```

Используется стандартная цепочка авторизации AWS. Не помещать ключи в командную строку, манифест или Git. Скрипт сохраняет приватную квитанцию с idempotency tokens до первого создания, затем дописывает новые ID/ARN. После сбоя повторить **ту же команду с той же квитанцией**. Она позволяет продолжить частично завершённое создание; потеря квитанции после неизвестного исхода требует сначала проверить ресурсы в Console, а не повторять запуск с новым префиксом.

6. Дождаться `ready and configuration verified` для всех пяти ролей. Скрипт сверяет модель, промпт, инструменты, Memory, лимиты, окно истории, execution role и настройки среды с сохранённым запросом. Сами runtime создаются AWS заново.
7. В Football UI зарегистрировать пять новых **базовых Harness ARN** из приватной квитанции, выставить формацию выбранного профиля (1-1-2 для M8), сохранить и перезагрузить профиль. Пользовательский endpoint создавать не требуется. Регистрация через скрипт не автоматизирована.
8. Запустить Pre-match Fitness и потребовать 5/5. При изменении Harness старая прогретая сессия может ещё использовать прежнюю конфигурацию: останавливать только известные собственные scrimmage-сессии, затем повторять проверку. Не останавливать чужие или активные матчевые сессии.
9. Играть один матч за раз, сохранять первичную статистику и полную валидность ответа; сравнивать обе стороны поля и соперников. Успешный Fitness не доказывает силу тактики или скорость реального inference.

Для отдельного эксперимента с памятью использовать `--profile memory-fwd1-m9`, новый префикс и отдельную квитанцию. Будет создан один STM-ресурс без LTM-стратегий и подключён только FWD1. Остальные роли получат явное `memory.disabled`: это важно, поскольку SDK может создать managed Memory при пропуске настройки. [AWS Harness Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html)

## Что проверено

- Три профиля проходят локальную валидацию структуры CreateHarness/CreateMemory актуальным botocore: 15 запросов Harness и 1 Memory.
- Проверены продолжение после частичного сбоя, повторный запуск без дубликатов, отклонение чужой квитанции и обнаружение конфигурационного расхождения.
- Дополнительно в том же аккаунте через CloudShell создан один FWD1 из фактического экспорта: READY, 13 полей совпали, регистрация сохранилась, Fitness 5/5. Это отдельная проверка API создания, не полный запуск `restore.py --apply`. Матч live44 проигран 0:2; сила тактики этим не подтверждена.
- Полный запуск в новом аккаунте пока **не проверен**. Offline-проверка и актуальный экспорт не равны успешному восстановлению после сброса.
- Ветка содержит и экспериментальный офлайн-контроллер `agentic_fc`; данный скрипт восстанавливает именно реальные AWS Harness с сохранёнными промптами, а не развёртывает этот контроллер.

```sh
.local/recovery-venv/bin/python -m unittest discover \
  -s research/v3/recovery -p 'test_*.py'
```

Контракт создания сверён с [AWS boto3 CreateHarness](https://docs.aws.amazon.com/boto3/latest/reference/services/bedrock-agentcore-control/client/create_harness.html). Все генерируемые ID и приватные квитанции должны оставаться в `.local/`, которая исключена из Git.

Для M8 в портале выставить 1-1-2; для M7 и M9 — 1-2-1. Промпты и модели M7/M8 одинаковы. Контроль live57 выигран 7:0, Practice01 — 3:1; эти игры не доказывают оптимальность состава. Для продолжения старой квитанции используйте её исходный commit и bundle: хеш комплекта защищает от смешивания разных планов.
