# Восстановление текущего быстрого FWD2 после сброса

Экспериментальная конфигурация: четыре исходных M8 Harness и один fast FWD2,
формация1-1-2. Это временный кандидат, не доказанный победитель. Актуальные
результаты и ограничения: [cohort06](../research/v3/ranked-batch-06.json),
[cohort07](../research/v3/ranked-batch-07.json), [HANDOFF](../HANDOFF.md).

Исходники действующей политики — commit8b31760, PLAYER_ID=4. Режим по умолчанию — stance; FWD2_MODE=probe-wide не включать. Последующие коммиты
сохраняют отчёты и упаковку; точные хеши файлов находятся в `artifact.json`.
Старый `pilot.py --apply` требует старые приватные ресурсы Workshop и **не
является рецептом восстановления в новом аккаунте**. Используйте этот порядок.

1. Восстановить пять исходных Harness по
   [M8 recovery](../research/v3/recovery/README.ru.md), профиль `baseline-m8`.
   Сохранить пятый Harness как откат. Зарегистрировать и проверитьFitness5/5.
2. В выбранном коммите репозитория собрать LinuxARM64/Python3.13 архив из
   закреплённых зависимостей, без обращения к старому аккаунту:

```sh
python3 -m venv .local/fast-build-venv
.local/fast-build-venv/bin/pip install \
  --target .local/fast-path-v2/dependencies \
  --platform manylinux2014_aarch64 --python-version 3.13 --only-binary=:all: \
  -r runtime_v1/requirements.lock.txt
python3 fast_path_v2/build_package.py \
  --dependencies .local/fast-path-v2/dependencies
```

Сборщик проверяет версии, архитектуру ELF, размер и список исходников. Архив
остаётся в `.local/fast-path-v2/deployment.zip`; его хеш и хеши исходников — в
`fast_path_v2/artifact.json`. Перед загрузкой сверить хеш, выполнить локальные
тесты и сохранить выбранный коммит. Сборка сама ничего не развёртывает.

3. В **новом** Workshop через AWS Console/CloudShell загрузить архив в его
   существующий code bucket под отдельным префиксом. Создать отдельный AgentCore
   Runtime: CodeZip, Python3.13, entrypoint `main.py`, существующая execution role
   этого Workshop, network PUBLIC, idle900s/maxLifetime28800s.
   Environment: `PLAYER_ID=4`, `BUILD_COMMIT=<коммит с проверенными исходниками>`.
   `FWD2_MODE` не задавать либо явно `stance`; диагностический `probe-wide` выключен.
   Не переносить старыеARN/account/sessionID и не менятьIAM ради восстановления.
4. Сохранить новую приватную квитанцию с RuntimeARN, версией, хешем архива и
   настройками. ДождатьсяREADY и сверить конфигурацию. Регистрация и создание
   нового Runtime не автоматизированы этим сборщиком.
5. Пройти нативный контракт на своём отдельном тестовомsession, затем заменить
   только FWD2 в портале на новый RuntimeARN. Остальные4Harness и1-1-2 сохранить.
   ТребоватьFitness5/5 и проверку свежей игровой сессии. По указанию владельца
   новые Practice/Benchmark запрещены; оценка — блоками по пять реальных игр. Останавливать
   только собственные диагностические сессии. При сбое вернуть сохранённый
   исходныйFWD2Harness и повторитьFitness.

Проверено: архив собран локально из сохранённых закреплённых LinuxARM64
зависимостей, его исходники сверены с8b31760. Полное создание и матч в новом
Workshop ещё **не проверены**. Локальная сборка не подтверждает доступность
моделей/ролей в будущем аккаунте и не доказывает10мс полного пути.
